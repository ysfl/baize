# 白泽 AI 接入

## 元信息

- 这是白泽的公开 Skill，帮助 AI 客户端在用户已经安装并登录 Baize MCP 后完成自然语言任务。
- Skill 负责判断何时使用白泽、选择工具和组织步骤；MCP 负责调用，白泽账号权限负责最终授权。
- 当前公开 MCP 工具是连接检查、节点列表和单节点基础状态查询，均为只读。

## 适用场景

当用户想了解白泽节点是否在线、查询某台服务器的基础状态、按名称或特征寻找节点，或需要从白泽开始一次远程运维判断时使用。

以下情况不要强行使用本 Skill：用户没有白泽实例、没有可用的 Baize MCP 连接，或问题只涉及本地文件而与白泽无关。

## 前置阅读

1. 先查看可用工具中是否存在 `baize_connection_status`、`baize_agents_list` 和 `baize_agent_get`。
2. 需要安装时，引导用户使用 [AI 接入安装入口](https://github.com/ysfl/baize/blob/main/scripts/install-ai-access.sh)，不要把它与白泽产品安装入口混淆。
3. 已经安装过 MCP 或 Skill 需要更新时，引导用户使用 [AI 接入升级入口](https://github.com/ysfl/baize/blob/main/scripts/upgrade-ai-access.sh)，不要使用白泽产品升级入口；升级后提醒用户重启 AI 客户端。
4. 需要了解部署、升级、恢复或 MCP 不可用时，阅读 [AI 远程任务使用指南](https://github.com/ysfl/baize/blob/main/docs/ai-remote-tasks.md) 和 [Baize MCP](https://github.com/ysfl/baize-mcp)。

## 输入

- 用户的自然语言目标，例如“看看生产数据库”“哪些节点离线”“查一下 web-01 的状态”。
- 已连接 MCP 提供的工具和结果。
- 用户补充的名称、别名、系统、版本、状态、分组等业务特征，以及当前工具明确支持的其它筛选条件。

不要要求用户重复提供 MCP 已保存的地址、登录会话或密码，也不要要求用户为了查询先记住节点 UUID。

## 输出

- 先给出简短的查询结论，再说明使用了哪个节点或候选。
- 需要用户选择时列出少量候选的显示名称、状态和必要的系统信息。
- 对列表、分页和空结果明确说明范围；不要自动遍历全部节点。
- 绝不输出地址、密码、会话凭据、私钥或 MCP 配置中的秘密。
- 当前只读工具没有执行远程变更的能力；不要把计划中的写能力描述为已可用。

## 执行阶段

1. **确认连接**：先调用 `baize_connection_status`。若失败，说明需要在本机登录或检查 MCP 安装，并链接公开指南。
2. **定位目标**：用户说的是名称、别名、主机名、系统、版本或状态时，调用 `baize_agents_list` 搜索或筛选。用户记得 UUID 时也可以直接使用，但不把 UUID 当成必填前置条件；只使用当前工具定义中实际存在的筛选参数。
3. **处理匹配**：只有一个合理候选时，仅在后续工具调用中使用返回的 ID；有多个候选时展示候选并请用户选择；没有候选时询问更多特征，不猜测目标。
4. **读取详情**：对确定的节点调用 `baize_agent_get`，只读取完成当前问题所需的基础状态。
5. **继续判断**：如果用户要做远程变更，说明当前 MCP 版本只读，并引导其回到白泽控制台和公开远程任务指南；不要模拟写入或自行构造未公开接口。
6. **总结结果**：保留状态、系统、版本、心跳等会影响判断的字段；按需继续分页，不把大段原始响应塞进对话。

## 边界与异常处理

- MCP 的工具结果受当前登录账号的白泽权限范围限制；遇到拒绝时如实说明“当前账号没有权限”，不要绕过权限。
- 连接失效、找不到资源、请求受限和服务暂时不可用要分别说明，并给出下一步，不展示底层 URL、Token、追踪信息或原始错误响应。
- 自然语言目标与多个节点相似时，宁可停下来确认，也不要依据 IP 片段、日志片段或模糊主机名自动选择。
- 结果过多时使用分页和筛选；结果为空时不要把空结果解释为白泽中不存在任何服务器。

## 降级与回滚

- MCP 不可用时，先引导用户重新执行公开 AI 接入安装器或在 AI 客户端中检查 MCP 配置。
- 只有 MCP 没有覆盖的公开能力，才引导高级用户查阅白泽公开 API 或控制台；不要把 Skill 变成万能 API 转发器。
- 本 Skill 不修改白泽实例、不保存凭据，也没有需要回滚的远程变更。

## 协作与交接

- 安装问题交给 [AI 接入安装指南](https://github.com/ysfl/baize/blob/main/docs/ai-remote-tasks.md)。
- 白泽产品部署、升级、备份和恢复交给 [白泽部署与用户文档](https://github.com/ysfl/baize)。
- MCP 运行文件、版本和更新记录交给 [Baize MCP Releases](https://github.com/ysfl/baize-mcp/releases)。
- 需要人工确认的写操作交给白泽控制台；Skill 不另造确认、审批或审计流程。

## 规则

1. MCP 优先，公开文档负责解释和恢复，公开 API 负责高级集成；三者不互相复制。
2. 用户记名称和业务特征，系统管理节点 ID；唯一匹配才继续，多个匹配必须确认。
3. 先读取、后判断、再建议动作；当前公开 MCP 版本不得执行写操作。
4. 不索取、不回显、不记录白泽地址、用户名、密码、Token、Cookie、私钥或会话内容。
5. 只使用公开链接和当前已发布能力；未来方向必须明确标为未来，不能当作现有工具。
