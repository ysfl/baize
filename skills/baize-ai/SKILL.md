# 白泽 AI 接入

## 元信息

- 这是白泽的公开 Skill，帮助 AI 客户端通过受控 Baize API 或 Baize MCP 完成自然语言任务。
- Skill 负责判断何时使用白泽、选择工具和组织步骤；API 工具和 MCP 都使用带角色的白泽账号，权限、风险控制、任务记录和审计由白泽服务端最终决定。
- 当前公开 MCP 工具覆盖连接检查、节点查询与运行概览、节点与平台观察、只读运行态诊断、告警、命令模板与命令计划、远程任务闭环（直接执行、派发、进度、按需输出、取消）和本机工作流状态；受控 API 工具可直接调用白泽公开的远程任务能力。写工具只调用白泽已发布的行为，最终权限、风险控制、任务记录和审计由白泽处理。

## 适用场景

当用户想了解白泽节点是否在线、查询某台服务器的基础状态、按名称或特征寻找节点，或需要从白泽开始一次远程运维判断时使用。

以下情况不要强行使用本 Skill：用户没有白泽实例、没有可用的 Baize API 或 MCP 连接，或问题只涉及本地文件而与白泽无关。

## 前置阅读

1. 先查看可用工具中是否存在受控 Baize API 工具；没有 API 工具时，再查看 `baize_connection_status`、`baize_agents_list`、`baize_agent_get`、`baize_overview_get`、`baize_agent_observe` 等 MCP 工具。
2. 需要安装时，引导用户使用 [AI 接入安装入口](https://github.com/ysfl/baize/blob/main/scripts/install-ai-access.sh)，不要把它与白泽产品安装入口混淆。
3. 已经安装过 MCP 或 Skill 需要更新时，引导用户使用 [AI 接入升级入口](https://github.com/ysfl/baize/blob/main/scripts/upgrade-ai-access.sh)，不要使用白泽产品升级入口；升级后提醒用户重启 AI 客户端。
4. 需要了解部署、升级、恢复或接入不可用时，阅读 [AI 远程任务使用指南](https://github.com/ysfl/baize/blob/main/docs/ai-remote-tasks.md) 和 [Baize MCP](https://github.com/ysfl/baize-mcp)。

## 输入

- 用户的自然语言目标，例如“看看生产数据库”“哪些节点离线”“查一下 web-01 的状态”。
- 已连接的 Baize API 或 MCP 工具和结果。
- 用户补充的名称、别名、系统、版本、状态、分组等业务特征，以及当前工具明确支持的其它筛选条件。

不要要求用户重复提供本机接入已经保存的地址、登录会话或密码，也不要要求用户为了查询先记住节点 UUID。

## 输出

- 先给出简短的查询结论，再说明使用了哪个节点或候选。
- 需要用户选择时列出少量候选的显示名称、状态和必要的系统信息。
- 对列表、分页和空结果明确说明范围；不要自动遍历全部节点。
- 绝不输出地址、密码、会话凭据、私钥或接入配置中的秘密。
- 任务、计划和结果只保留完成当前判断所需的有限字段；不要要求或回显环境变量、操作者身份、完整任务输出或凭据。

## 执行阶段

1. **确认连接**：如果存在受控 API 连接工具，先检查 API 连接；否则调用 `baize_connection_status`。若连接失败，说明需要在本机登录或检查接入安装，并链接公开指南。
2. **定位目标**：用户说的是名称、别名、主机名、系统、版本或状态时，调用可用的节点列表工具搜索或筛选。用户记得 UUID 时也可以直接使用，但不把 UUID 当成必填前置条件。
3. **处理匹配**：只有一个合理候选时，仅在后续工具调用中使用返回的 ID；有多个候选时展示候选并请用户选择；没有候选时询问更多特征，不猜测目标。
4. **读取详情**：对确定的节点读取完成当前问题所需的基础状态，不自动扩大查询范围。需要更深入判断时，可在同一节点上使用节点观察或只读诊断工具，或先读一次运行概览缩小范围。
5. **准备远程任务**：需要动作时先列出目标、目的、命令或模板、风险、预期结果和回滚方式。用户已经给出命令或只需一次性维护时，不要先查模板，直接使用受控远程任务 API；模板只用于固定、重复和便于维护的常规命令。
6. **选择工作流**：普通远程任务不要求 `templateId`，也不要求先创建命令计划。只有用户明确需要计划，或服务端返回 `approvalRequired=true` / 明确要求审批时，才进入命令计划审批流程；不能因为命令风险等级或工具目录中存在审批工具就自行发起审批。
7. **执行与跟踪**：用户确认目标和动作后，调用受控 API 的远程任务创建工具；没有 API 工具但 MCP 提供等价的直接任务工具时使用 MCP。服务端要求风险确认时按返回结果补充确认；需要停止时调用任务取消工具，查询进度使用任务查询工具。
8. **总结结果**：保留状态、系统、版本、心跳和任务进度等会影响判断的字段；按需继续分页，不把大段原始响应塞进对话。

## 边界与异常处理

- API 和 MCP 的工具结果都受当前登录账号的白泽权限范围限制；遇到拒绝时如实说明“当前账号没有权限”，不要通过切换接入方式绕过权限。
- 连接失效、找不到资源、请求受限和服务暂时不可用要分别说明，并给出下一步，不展示底层 URL、Token、追踪信息或原始错误响应。
- API 返回 403 时停止，不改用 MCP 重试同一动作；API 返回 401 或连接失败时，才检查登录会话或切换可用接入方式。
- 自然语言目标与多个节点相似时，宁可停下来确认，也不要依据 IP 片段、日志片段或模糊主机名自动选择。
- 结果过多时使用分页和筛选；结果为空时不要把空结果解释为白泽中不存在任何服务器。

## 降级与回滚

- API 工具不可用时使用 MCP；MCP 也不可用时，再引导用户检查接入安装或使用白泽控制台。
- API 和 MCP 都只能使用明确的、受控的白泽能力；不要把 Skill 变成万能 API 转发器。
- 本 Skill 不保存凭据，也不绕过白泽权限、风险确认、服务端要求的审批或审计；普通 API 远程任务同样会留下任务和审计记录。
- 远程任务的回滚方式必须由操作者和白泽工作流共同确认；任务创建成功不等于动作已完成。

## 协作与交接

- 安装问题交给 [AI 接入安装指南](https://github.com/ysfl/baize/blob/main/docs/ai-remote-tasks.md)。
- 白泽产品部署、升级、备份和恢复交给 [白泽部署与用户文档](https://github.com/ysfl/baize)。
- MCP 运行文件、版本和更新记录交给 [Baize MCP Releases](https://github.com/ysfl/baize-mcp/releases)。
- 需要人工确认的写操作沿用白泽服务端返回的要求；Skill 只组织确认信息和调用顺序，不把审批强加给不需要审批的普通远程任务。

## 规则

1. 受控 API 优先，MCP 作为兼容入口，公开文档负责解释和恢复；三者不互相复制。
2. 用户记名称和业务特征，系统管理节点 ID；唯一匹配才继续，多个匹配必须确认。
3. 先读取，再根据任务类型选择普通远程任务或命令计划；普通任务不要求模板和审批，审批申请、审批决策、执行和取消都必须按服务端状态及用户明确意图进行。
4. API 和 MCP 都不能自行授予权限；遇到 403、409、过期、风险确认或服务端明确的审批要求必须停止并说明。
5. 模板是可选的固定命令复用工具，不是远程任务的通用前置条件；用户已提供命令时不得要求先创建模板。
6. 不索取、不回显、不记录白泽地址、用户名、密码、Token、Cookie、私钥或会话内容。
7. 只使用公开链接和当前已发布能力；未来方向必须明确标为未来，不能当作现有工具。
